# 工作后知识提炼

## 本次变化

原技能侧重知识库建设、证据、分类和一致性检查。工作收尾时，维护者还需要从任务材料中识别知识增量，再决定更新、补充、引用、退役或保持不变。现在将这条路径放入 description 和主入口，并由取舍方法及对照实例支撑；没有新增自动评分或决定是否入库的脚本。

通用源码统一为 `skills/knowledge/`，公开名称为 `knowledge`；原有只读工具接口保持。项目事实、目录表、日志政策和强制工作规则由使用项目提供，不进入通用技能。已经安装旧名 `maintain-knowledge` 的项目不会随源码改名自动升级；更新项目安装及入口时应替换旧名，避免同时加载两份。此次未改已有项目安装副本或其工作规则。

## 判断方法

候选知识来自最终采用的变化、已查明或纠正的事实、已确认的选择及原因。共享收录先于改写：逐条确认读者与用途、适用范围、事实或决定权威、证据状态和现有知识增量。来源是个人与内容仅适用个人是两件事；个人发现可经核验成为项目事实，个人要求不能靠去人称变成团队政策。修改事实的主要维护位置，只有独立用途与责任成立才新建主题。原处资料已维护时建立入口，原说明失效时更新或退役，真正没有增量时不产生文件。

一次性经历与知识不是按寿命或出现次数机械区分：一次确认的数据丢失风险值得保留；仍受支持版本的临时绕过需要给出条件和退出范围；纯内部改名可以没有知识增量；没有代码改动的调查也可能推翻已有错误指引。缺少来源或无法读取现有库，属于未能判定，不能冒充无需维护。

教学实例解释为什么选择不同处置，再对合格候选示范具有条件和依据的正文。个人路径、工具或助手偏好不自动转存；无共享增量允许完全不写。必要的事故因果顺序与决定沿革保留，聊天过程和任务日记不进入主题。实例是方法演示，不是项目默认事实。评测采用不同任务输入，答案不进入运行资源。

## 一手资料与取舍

- [Software Engineering at Google 的文档章节](https://abseil.io/resources/swe-book/html/ch10.html)：按读者任务写作、明确维护者及主要文档、复用已有工程流程。采用这些责任和使用思想，不采用允许先交粗稿的建议作为本项目交付标准。
- [Anthropic 技能编写实践](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)：明确触发、按判断风险选择自由度、按需读取资源、用实例解释输出要求。没有复制厂商示例中的固定清单或统一测试数量。
- [Agent Skills 输出评测](https://agentskills.io/skill-creation/evaluating-skills)：用新上下文执行任务，观察完整结果，区分包检查、模型执行和版本对照；不能把准备案例或脚本成功算成判断能力验收。
- [Skills CLI](https://github.com/vercel-labs/skills)：复用已有项目安装机制，不另建插件或安装体系。

项目内原始任务与旧技能副本用于发现问题，但不作为运行必读资料或技能正文中的历史记录。知识格式继续按项目选择；随包保留的 OKF 原文与许可证未修改。

## 主动使用与权限

触发不再限于工作结束后的明确请求。description覆盖需要项目背景的理解、开发中可观察的行为变化、排障发现的知识冲突，以及版本或政策改变使旧操作失效。主文在这些决策时点路由到项目查询或取舍方法；不将知识维护推迟到用户提醒时。

主动识别不等于自动写入所有文件。只读任务仍只读；已授权实现或修复中按项目约定同步必要说明，禁止把每次内部格式变更变成全库审计或额外汇报。没有新增事实时不强求写文档。明确的文件范围、项目规则和外部发布权限不因技能触发而改变。

可选的 `agents/openai.yaml` 显式保持 `allow_implicit_invocation: true`；通用frontmatter仍只有name和description，不使用会关闭模型自主调用的字段。该配置允许调用，不证明模型实际选择正确。技能必须由宿主加载到可发现列表中，项目安装不是全局后台任务。

依据：[OpenAI 技能调用](https://developers.openai.com/codex/build-skills)、[Claude Code 技能可见性](https://code.claude.com/docs/en/skills)、[Agent Skills 描述与自然触发](https://agentskills.io/skill-creation/optimizing-descriptions)。这些资料的宿主设置不反向成为通用方法依赖。

## 评测入口

执行 `tests/test.sh` 检查现有工具及独立安装目录中的回归。行为案例位于 `evals/cases.json`，包含工作后提炼与共享收录边界的对照任务。使用 `evals/prepare_case.py <case-id> --output <独立空目录>` 只生成任务、事实材料和原知识，不生成评审答案。

比较旧版与当前版本时，对两者使用相同模型、任务、权限和初始文件，分别建立新会话。只向任务环境提供运行资源 `SKILL.md`、`references/`、`scripts/`，不暴露 `evals/`、`tests/` 或本维护说明。检查实际读取、文件修改及最终结论，允许措辞不同，但不允许关键条件遗漏、虚构原因、越权写规则、重复正文或无意义落盘。通过格式检查不能抵消这些错误。

自然发现和显式指定技能分别验证。题目已经明确要求读取技能时，结果不能用来宣称自然触发成功。没有模型任务结果时，如实记录未运行；不发布准确率或跨模型效果结论。

新增8项 `implicit-` 案例不点名技能，4项应主动使用，4项是近邻反例。`expect_invocation`和评审说明只交给评审者；任务模型只接收TASK.txt、原始项目输入及正常宿主技能发现列表。必须观察实际加载和读写轨迹，不能以模型回答“应该使用”或CLI列举成功代替自然调用测试。

共享收录新增四个对照案例：curation-shared-authority、curation-scoped-environment、curation-causal-incident、curation-personal-only，分别检查个人偏好与已接受决定、本机绕过与共享环境限制、聊天顺序与必要事故因果、没有共享增量时的零写入。验收同时看主题更新、来源与状态，不能用禁词扫描代替判断。
