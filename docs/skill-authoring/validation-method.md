# Skill 验证方法

Skill 验证同时检查包结构、资源行为和 Agent 在真实任务中的表现。静态检查只能证明可发现和格式有效，不能代替行为验证。

## 在测试前确定验收契约

从用户目标、Skill 职责和适用产物契约中预先列出：

- 必须覆盖的输入、数值目标、状态和 authority；
- 不得制造、泄漏或越权处理的内容；
- 必须满足的结构和语义不变量；
- 每项要求的权威证据；
- 阻断错误、非阻断缺陷和允许的表达差异；
- 测试何时通过、何时停止以及何时需要用户决策。

不要在看见输出后不断提高标准。新发现的普遍缺陷可以进入下一版验收契约，但当前运行必须保留原始判定边界，避免用移动终点解释结果。

## 建立测试层次

### 静态验证

检查目录、frontmatter、名称、直接链接、占位符、文件编码和其他可机械判定的约束。运行仓库规定的验证命令，并确认验证器确实覆盖当前声明的要求。

### 资源验证

实际运行 scripts；使用真实输入填充模板；检查输出解析、渲染、只读边界、错误处理和跨环境假设。不得只阅读实现后推断其可用。

### 前向测试

使用全新 Agent 和接近真实用户表达的任务。测试 Agent 不应看到预期答案、已知缺陷、拟议修复、前一轮结论或其他污染样本。

从以下类型中选择足以覆盖关键行为差异的样本：

- 一个典型任务，证明主要工作流可用；
- 一个不同领域或结构的保留任务，检查是否泛化；
- 对关键开放问题、冲突、权限或失败状态的压力任务。

样本数量取决于要排除的不确定性。一个任务已经覆盖全部关键性质时不为凑数量重复测试；不同路由、授权边界或失败行为无法由同一任务证明时再增加样本。

测试性质而不是逐字答案。除非输出本来就是固定格式，不要用整篇 golden answer 限制合理的专业差异。

## 选择足够的行为证据

根据要证明的行为选择验证方式：

- 直接生成任务同时对照原始输入、适用契约和完整产物，检查要求覆盖、语义保持、结构约束与未验证主张。
- 转换任务比较来源与结果，确认状态、关系和不确定性没有在转换中漂移。
- 路由任务记录 Agent 实际读取的 references，区分知识不存在、知识未加载和加载后未执行。
- 工具或副作用任务检查授权边界、实际状态和失败行为，而不把“执行过步骤”当作完成证据。
- 只有需要判定首次生成行为、比较候选版本、复现缺陷或让独立审查结论可归因时，才保存并标识一个不可变候选快照。审查结论只适用于该快照。

需要逐项判定时可以使用 `PASS`、`FAIL` 和 `NOT VERIFIED`。`PASS` 指向证据，`FAIL` 说明违反的契约与修复条件，`NOT VERIFIED` 不得按通过处理。只检查产物内部一致性不能证明输入覆盖；每项必须覆盖的输入都应进入其权威位置，或被有理由地排除、标记冲突或保留为开放项。

## 修复和重新验证

根据失败层级修复最接近根因的位置，再运行受影响的验收项和足以发现相邻回归的保留测试。只有当改动可能影响整个产物契约时才需要全量复验；不要因为发生过一次缺陷就永久引入全流程循环。

当所有阻断项有证据地通过、任务因缺少 authority 或外部状态无法继续，或预先定义的停止条件成立时结束验证。诚实保留未通过或未验证项，不以修改次数、耗时或已完成工作量降低验收标准。

## 诊断失败层级

| 观察 | 首选诊断 | 优先修复位置 |
|---|---|---|
| Agent 不知道规则 | 知识缺口 | 对应 reference |
| 规则存在但没有被读取 | 路由缺口 | `SKILL.md` 路由条件 |
| Agent 能识别规则、生成时却遗漏 | 执行缺口 | 将约束移到产生该决策的位置；必要时使用字段契约、模板或验证器 |
| 不同审计者对通过标准理解不同 | 契约缺口 | 谓词、作用域、证据和停止条件 |
| 错误持续逃过检查 | 验证缺口 | 验收契约、测试用例或验证器 |
| 修复一个极端后滑向另一个极端 | 过拟合 | 抽象稳定维度并补充停止条件 |

只有证据指向知识缺口时才增加专业说明。执行缺口继续堆叠同义提醒，通常只会增加上下文噪声。

## 使用独立验证

当独立样本能够消除共享上下文、答案泄漏或作者盲点带来的关键不确定性时，使用另一名全新 Agent 执行保留任务。验证 Agent 不继承作者的完整对话，不接收预期答案或拟议修复，并重新读取当前 Skill 源码和任务输入，依据同一验收契约判定。

不要把独立 Agent 的数量当作质量证据。若额外一次验证不会改变对目标行为的判断，就不应仅为形成仪式而增加它。

## 保存长期证据

仓库长期保存：

- 泛化后的工程原则和实现标准；
- 能复现重要行为的测试输入；
- 基于性质的验收断言；
- 必须防止复发的最小回归样本；
- 确定性验证脚本。

原始长对话、每轮完整生成物和临时审计日志默认作为测试运行产物，不进入 Skill，也不必全部提交。只有当某个原始样本是复现缺陷所必需时，才将其最小化后保存到仓库级测试目录。

提交前运行 [CONTRIBUTING.md](../../CONTRIBUTING.md) 规定的命令，并检查工作树中没有 Agent 安装副本、测试污染物或与当前修改无关的文件。
