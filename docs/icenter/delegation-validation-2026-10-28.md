# iCenter 托管状态与消息后缀验证

## 范围与依据

变更基线为 `c6cd760d33beecb3a20db1548b9c236ba9597a4e`。用户要求代办期间显示托管状态，支持自定义消息后缀；结束默认清为无状态，用户指令或会话已有恢复目标时使用该目标，不额外保存旧状态。

运行环境为 Windows、Node.js 26.8.1、iCenter 12.6.8。当前适配版本由 [client-version.json](../../skills/icenter/scripts/client-version.json) 维护。验证使用已登录的本人账户；消息测试的收件人为本人。

## 实现与职责

- 新增 `user-status`、`set-user-status`，SDK 会话提供对应方法。设置校验成功回调和原账户的回读结果；默认目标为 `None`，显式目标使用已登记枚举和自定义条目 ID。
- `expectedCustomId` 从本次结果或会话取得。当前状态不符时保持原值。该比较不具备服务端原子条件更新语义，无法锁住用户手动操作；调用方协调共享账户的修改。
- 自定义状态条目的查询、保存和删除复用通用 SDK，没有新增另一套 CRUD、恢复文件或后台服务。状态枚举 `22a3.b` 从当前客户端核对并登记。
- 可见后缀在 `sendText` 中拼接，回复调用沿用同一入口；CLI 增加 `--suffix-file`。后缀默认关闭，发送核对完整正文。有效隐形来源标记按完整可见正文重新计算。
- 条件参考说明托管名称、流程就绪、结束目标、条目复用及逐字内容例外。调用方负责代办流程，iCenter 提供状态与发送操作；watcher、dispatcher 没有修改。

## 真实客户端结果

| 路径 | 已观察结果 |
|---|---|
| SDK 状态操作 | 创建测试条目，保存后当前状态仍为 `None`；设置 `Custom` 后回读取得测试文字与对应 ID；带条件清除后回读为 `None`。 |
| 条件不符 | 当前为 `None` 时，带测试条目 ID 请求设置 `Busy`，返回 `unchanged/current-status-differs`，当前状态保持 `None`。 |
| CLI 状态操作 | 预览、按字符串 ID 设置、查询、带条件清除均取得对应结果；客户端回读的数字 ID 与命令输入指向同一条目。 |
| 消息后缀 | CLI 预览含换行和后缀；向本人发送一条测试消息，取得 `client-confirmed`；按消息 ID 重读的完整文字与预览一致。 |
| 清理 | 两轮各自创建的测试条目均已删除，列表确认不存在；最终当前状态为 `None`。没有修改其他状态条目或启动实际托管流程。 |

本次核对了客户端状态编辑器的条目容量、名称计数和默认图标行为，证据来自当前代码。状态写入的验证证据是成功回调及服务端查询结果，不是截图或其他账户的观察。
