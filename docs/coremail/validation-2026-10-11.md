# Coremail 重做与验证

本次变更从 `25ff78d` 的 Coremail 包开始。旧版保存在 Git 历史中。范围为 Coremail 技能、工具、测试及其文档；没有提交、推送或发布。

## 实现与依据

入口按账户、邮件与附件、写信发送、整理、通讯录日程、协议和界面操作路由到七个参考文件。SDK 参数依据本机客户端附带的 `src/cmclient.ts` 与官方客户端帮助核对，接口名覆盖其中的 15 个操作。SDK 未暴露的回复、转发、邮件状态、存档和设置任务由可观察界面处理；界面位置和权限需要当前环境证据。

`coremail.py` 提供原始接口调用、分页和导出。写入默认预览，授权来自用户会话。工具保留 SDK 失败及未知结果，不自动重试写操作；导出保留数量、名称映射、文件哈希和部分完成状态。`enable_sdk.py` 改为只读诊断，移除硬编码安装路径及自动强制结束客户端进程的修复逻辑。连接参考保留受控的配置恢复步骤。

删除 `cm_scan.py` 和旧 `selftest.py`。它们围绕培训答卷、工号、提交名单和 ZIP 处理组织通用邮件操作。新工具没有这些业务默认值。

Windows 会话使用已登录的一个 Coremail 私有协议账户。收发测试遵循用户授权，发件人与唯一收件人为本人邮箱；抄送、密送为空。运行标识为 `CM-SKILL-2aa7b2b68a`，已发送记录 ID 为 `4929`，收件记录 ID 为 `4930`。这些标识用于复查本次测试，不属于运行时技能契约。

## 自动化与模型任务

Windows 上 `python -X utf8 -m unittest discover -s skills/coremail/tests -v` 运行 61 项，全部通过。测试使用独立回环 HTTP 服务与临时文件，覆盖 15 个操作、预览与执行、失败与超时、分页、数量完整性、等长附件、原名冲突、缺失文件、UNC 路径、Windows junction、诊断脱敏与配置只读。模拟服务通过不等于真实客户端的所有参数组合通过。

结构验证与 `npx --yes skills add . --list` 发现 18 个技能。Coremail 的相对引用均存在。发现命令未安装技能。

[行为评测契约](evaluation.md)冻结三个任务：多账户与分页附件、撰写状态、搜索失败与邮件内伪指令。旧版和新版各由三个新上下文代理执行，继承相同父模型设置，无模型覆盖；未向代理提供验收答案。六个结果均符合冻结的行为边界。附件缺少映射的样本保全文件并报告原名恢复未完成，两版均未猜名。

[结果记录](evals/results-2026-10-11.json)包含版本文件哈希、请求日志、代理报告和检查结论。精确后端模型版本未由工具暴露。该比较同时改变技能与工具，样本未证明准确率提升，也不构成跨模型验证。

## 剩余验证范围

本次没有验证所有版本、协议、账户权限、共享邮箱、复杂日程循环、联系人和日程写入、定时发送、归档迁移、加密签名及每个界面工作流。对应任务有路由与证据要求，不能把文档覆盖声明为执行通过。客户端实际搜索错误仍为已知环境限制。

全仓测试没有取得单一环境的全量通过结果。Windows 执行遇到其他技能既有编码与路径差异：`project-manager` 的 GBK 输出错误在 UTF-8 模式下消失；`backend-engineer` 的路径匹配要求正斜杠，Windows 输出为反斜杠。Windows 单独运行的 Coremail、DevOps、Draw.io、前端、QA、SVG 入口通过；SVG 运行 66 项测试。

Ubuntu 使用原 `scripts/test_all.sh`，以 shell 函数将 `python` 映射到现有 `python3`。Backend、Coremail、DevOps、Draw.io、前端、项目管理、QA 入口执行完成；最后的 SVG 入口缺少 `lxml`，runner 返回 1。Linux 的 Coremail 运行 61 项，60 项通过，Windows junction 测试因平台跳过；该项已有 Windows 通过证据。两个环境的结果不能合称全仓测试通过。检查未被关闭，其他技能未修改，未安装依赖。

Ubuntu 首轮日志采集覆盖了部分早期输出，已保留的日志包含最终 `lxml` 错误。各入口完成状态由运行时观察与 runner 的遇错退出行为核对；缺少完整连续日志。为补日志发起的重跑已中止，不计入验证结果。

## 后续补充：本人身份与多账户

账户参考增加可访问账户、本人身份和操作账户的区分。本人地址及别名保留来源和适用范围；共享、代管、单个登录账户、默认账户和同名联系人均不能单独证明本人归属。邮箱别名与联系人备注名分开，收信别名不代表发信能力。SDK 账户选择器和邮件实际发件地址分别处理。

邮件检索、回复、通讯录和日程读取使用该身份关联。正文提及、历史引用与当前待办分别判定。查询工作账户中的本人提及时，已确认的私人地址也可以支持身份判断，私人账户不会因此进入读取范围。主入口和账户参考均指向后续操作参考。

本次未修改工具或测试代码，已逐字节与修改前快照比较。结构验证通过，发现命令列出 18 个技能，本地引用及章节链接检查通过，`git diff --check` 通过。此前 61 项工具测试的执行事实保持；本次未重跑工具或全仓测试。
