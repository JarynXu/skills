# Coremail 程序化客户端验证

原版来源为 `94755dc20fecbd9afc1c8d85d6cd5b9a60d920e7`，本次实现对应承载本记录的 Git 提交。原版快照、实际输入、查询输出及附件保留在忽略目录 `.tmp/coremail-client-20261013/`，包含个人数据，不进入技能包。运行环境为 Windows、CMClient 4.2.3.1614、CEF Chromium 146.0.7680.179、Python 3.14.6、Node.js 26.8.1 和 Windows PowerShell 5.1。客户端返回一个账户。

## 接口与职责

客户端主体是 wxWidgets，正文、编辑器和日历嵌入 CEF。单用 SDK 不能覆盖客户端设置与发送；单用 CDP 不能覆盖原生表单。本次保留 SDK 的十五个已声明接口，增加 CEF 页面工具及 Windows 原生适配器。入口按任务加载参考，SDK、页面对象、原生控件和业务结果承担各自的证据。

连接工具绑定 CMClient PID、程序路径和回环监听。页面工具绑定当前 target ID、完整 URL 和原生消息桥。原生工具绑定进程、窗口标题、HWND、控件 runtimeId 和名称，读取标准 Edit 值、Button 复选状态及 MSAA 列表项。预览不派发业务动作；派发、成功和完成分开报告。

工具只使用 Python 标准库、Node 内置 WebSocket 和 Windows 自带接口，没有 npm 依赖。wxRibbon 标题缺少可访问动作；标签导航使用当前标题条的 Windows OCR 锚点推算位置，再核对原生页面可见状态。该适配限于已核对的等距布局，不适用于任意按钮，不读取邮箱地址或邮件内容。系统设置中间按钮的定位也保留当前版本的组件边界。

运行时参考增加阅读页、写信页、日历及原生表单的入口，覆盖回复转发、旗标备注、联系人、日程、规则、提醒、存档和安全能力族。发送桥已实测；其他内部命令按源码路由标注，未宣称已执行。多账户、本人及别名契约保留；本次只有一个真实账户，没有多账户或别名发信的端到端证据。

## 真实入口执行

| 对象 | 观察与结论 |
|---|---|
| 启用 CDP | 用户确认没有未保存内容并授权重启。首次原型附加 `--remote-debugging-address`，客户端报 Unknown long option。移除该参数后建立回环 CDP；正式 `connect.py restart --pid … --force --apply` 再次启动成功，SDK 恢复。重启前后账户记录相同。主窗口关闭会收起到托盘，普通关闭不能充当进程退出。 |
| 页面发现与读取 | 正式 `client.cjs targets` 取得阅读、日历及小日历页面；`inspect` 读取当前页面。运行 User-Agent 提供 CMClient 版本，Chrome 字段提供 CEF 版本，二者没有混用。主程序文件版本资源为空。 |
| 设置查询 | 正式原生工具切换设置标签、打开系统设置，选择 MSAA 列表中的“操作习惯”，读取“新邮件弹窗的同时播放声音”。BM_GETCHECK 为 0，当前用户配置的 NewMailSound 为 false。两者支持该客户端系统设置关闭；未测试来信时声音播放，未核验账户覆盖或服务端条件。设置窗口关闭，标签恢复为邮件。 |
| 真实失败处理 | F3 没有按预期打开系统设置；搜索框焦点下出现了快速搜索选项。当前热键配置不足以证明全局快捷键含义。整窗 OCR 的识别结果不足以核对收件地址，已删除该实现。MSAA 子节点 ID 不是顺序整数；适配改用 AccessibleChildren 取得实际项。 |
| 目标与失败边界 | 真实入口拒绝不存在的 target、非写信页发送、不匹配的正文片段、变化的控件名称和非 CMClient 进程，共五项。错误保留为错误，没有派发对应动作。 |

开发时使用 computer use 观察客户端并研究设置入口。正式收发、原生确认、设置查询及独立模型查询均通过随包脚本执行。原生标签导航内部使用 Windows 图像与 OCR 接口；“无需 computer use”不表示整个实现没有使用屏幕像素。

## 全新上下文查询对照

[任务](../../skills/coremail/evals/no-desktop-client-task.md)与[验收](../../skills/coremail/evals/acceptance.md)在候选结果产生前固定。原版与候选使用 `gpt-6-luna / medium`、各自全新上下文。模型只取得任务、指定技能目录和私有输出目录，没有取得验收答案、作者脚本或另一份结果。明确指定技能不构成自动发现测试。

最初原版运行时没有 CDP，版本与提醒均未取得；该运行不能与准备后的候选直接比较。连接准备完成后，原版和候选依次操作同一个客户端，均从邮件页开始，禁止发信、改配置、启停客户端或操作草稿。

| 查询 | 准备后的原版 | 候选 |
|---|---|---|
| 本机版本 | 从 renderer 命令行取得 4.2.3.1614_WINDOWS，程序文件版本为空。 | 从已核对进程的 CEF User-Agent 取得 4.2.3.1614。 |
| 声音提醒与范围 | SDK 没有对应接口；没有程序化原生操作路径，状态与范围保留未知。 | 通过随包工具打开系统设置，读取原生复选状态为关闭，指出账户覆盖与服务端状态未知。 |

候选首次执行 targets 漏传 PID，工具返回 ARGUMENT，取得当前 PID 后继续成功；未把该失败隐藏为成功。模型实际读取入口、程序接口、原生适配器及能力路由。原版读取入口、连接账户、界面操作及 SDK 协议。

当前样本支持候选完成原版未完成的提醒查询。该比较没有分离指令与新增工具的贡献，也未验证所有模型或全部功能。执行记录保留了短原始输出及关键字段；部分长控件树、窗口枚举没有持久保存，不能作为完整动作审计。作者另存的原生状态、最终窗口枚举及配置读取支持当前结果，没有对全部草稿及客户端状态作前后快照比较。

独立查询后修正了重复端口参数、Windows 路径规范化和可选正文校验，补充了对应回归。连接工具增加独立 stop 入口，供 SDK 离线配置维护退出使用；restart 会重新启动，不能替代该步骤。stop 的底层退出机制已通过正式 restart 实测，独立入口真实预览后客户端仍运行，并通过不启动新进程的回归。查询所用的原生入口及设置取值契约未改变。
