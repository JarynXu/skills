# Complete quality-engineering learning path

Use this route when the agent lacks a broad quality-engineering model. For a focused task, follow the direct routes in `SKILL.md` instead.

1. Read `core/project-orientation.md` to establish product truth, test-system truth, environments, data, and release context.
2. Read `core/quality-model.md` to understand risk, evidence, coverage, authority, and completion.
3. Read `practices/risk-and-strategy.md` to convert consequence and uncertainty into a proportionate strategy.
4. Read `practices/test-design-and-oracles.md` to derive conditions and expected results systematically.
5. Read `practices/functional-and-integration-testing.md` to choose faithful levels for APIs, UIs, data, messages, files, devices, and integrated systems.
6. Read `practices/exploratory-and-regression.md` to manage discovery, smoke, sanity, and impact-based regression.
7. Read `practices/nonfunctional-testing.md` for performance, reliability, resilience, recovery, installation, upgrade, and disaster scenarios.
8. Read `practices/security-accessibility-compatibility.md` for specialized cross-cutting evidence and authorization boundaries.
9. Read `practices/test-environments-and-data.md` to understand environment fidelity, test identities/data, isolation, reset, privacy, dependency substitution, platform matrices, and production-safe validation.
10. Read `practices/automation-architecture.md` to build maintainable, deterministic automation and delivery integration.
11. Read `practices/defects-and-release-evidence.md` for diagnosis, defect evidence, retest, gates, and recommendations.
12. Read `practices/uat-and-production-validation.md` for business and operational acceptance without crossing decision authority.
13. Read `technologies/test-control-plane.md`, then only the applicable sections of `technologies/tool-routing.md`, to convert repository evidence into safe candidate verification commands without confusing discovery with execution authority.
14. Open `library/INDEX.md` when a testing mechanism, automation framework, integration model, property-based technique, contract rule, or security-testing method is unfamiliar or exact source-backed semantics matter. Learn only the relevant source pack, then return to the project.
15. Use `standards/index.md` for recurring terminology/standards lookup and `standards/sources.md` before incorporating or updating external material.

After learning, return to the actual product. Project rules, current versions, executable commands, supported environments, and observed behavior override generic recollection or a pinned library source that targets another version.
