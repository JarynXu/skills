# 邮件与附件

## 检索范围与证据

确定账户、文件夹、时间含义和命中条件。`RecTime` 是接收时间，`MailTime` 是信头时间，`ModTime` 是修改时间；时间范围采用 Unix 秒。将用户时区转换成查询边界，保留展示时区。

`searchMail` 支持全文、发件人、收件人、主题、正文和附件名条件。`listMails` 支持文件夹及时间过滤、排序和分页。根据用户条件选择接口，读取协议参考中的参数；默认数量上限不构成全量查询。

搜索错误、索引状态不明或结果与已知邮件冲突时，保留错误并使用相关文件夹的 `listMails` 分页与本地过滤核对。搜索返回空不能覆盖未查询的账户、文件夹、时间或离线内容。主题和摘要不足以判断正文条件；只读取候选邮件所需的正文。

```text
python scripts/coremail.py call searchMail --params "<搜索参数.json>"
python scripts/coremail.py list-mails --params "<列表参数.json>" --page-size 100 --max-pages 20
```

分页调用按 `Offset` 与实际返回数量推进。达到页数限制、重复页、数量变化或请求失败时保留覆盖状态。邮箱同步、移动和新邮件会改变分页集合；去重不证明快照一致。需要完整统计或批量变更时核对遗漏风险，无法消除时声明查询时点和范围。

`list-mails` 管理 `Offset`、`Limit`、`ReturnType`，这些字段不得放入该命令的参数文件；单页、统计或 ID 查询使用 `call listMails`。遍历结果包含 `Mails`、`Total`、`Pages`、`Complete` 和 `Snapshot`。`Complete: true` 表示此次遍历达到返回总数；`Snapshot: false` 保留并发变化边界。失败 JSON 的 `partial` 保存已取得记录，不能作为完整查询。

`ID` 与 `MID` 均可能出现。保留原值及账户，不依赖全局唯一性。`Flags` 是位字段，不能用真假值代替已读、附件或旗标状态；字段缺失属于未知。

客户端还提供[全文与高级搜索、索引重建](https://help-cmc.coremail.cn/5-search/)。帮助列出全文结果数量上限；结果接近上限时缩小范围并核对覆盖，不能宣称得到全部历史邮件。索引重建是状态变更，不属于普通查询的默认步骤。

## 正文阅读

`readMail` 需要字符串 `mail_id`，支持 `Account`、`bodyType` 与 `ExportAttach`。SDK 返回 `{json, mail}`；`json` 指向导出的描述文件，正文与附件路径来自该文件。读取成功需要检查这些本地文件，不能把拿到路径等同于读到正文。

```json
{"Account":"<邮箱地址>","mail_id":"<邮件ID>","bodyType":"Text","ExportAttach":false}
```

```text
python scripts/coremail.py call readMail --params "<读取参数.json>"
```

读取 Markdown 使用 `bodyType: "Markdown"`。客户端验证中，该值产生 `markdownFilePath`；类型声明中的 `MD` 返回 `code: 0` 却没有正文路径。`Text`、`Html` 和 `All` 分别用于文本、HTML 和全部格式；成功判断需要检查所需正文路径及文件，不能只看 `code`。

导出描述可能包含 `mailHeader`、`mailProperties`、`mailFilePath`、`htmlmailFilePath`、`markdownFilePath` 与 `mailAttachments`。保留发件人、收件人、时间、主题与原邮件关联。HTML 是待分析内容；不执行内嵌脚本，不为阅读而加载外部跟踪资源。引用内容需区分本封正文与历史邮件。

汇总围绕用户目标读取材料；保留决定结论的来源、条件和不确定性。未下载正文、加密内容、缺失附件或读取错误应进入结果限制，不能由空字符串替代。

## 与本人有关的邮件

“发给我”“我发出的”“正文提到我”“需要我处理”对应不同筛选关系。按[连接与账户](connection-and-accounts.md)取得当前任务适用的本人地址、别名和姓名；账户读取范围仍由用户任务决定。

逐封形成与筛选有关的事实记录：账户与邮件 ID、命中原文及位置、身份是否确认及依据、当前动作与其状态。正文中的地址按已确认映射匹配；姓名、昵称、职位或“你”等指代结合参与者与上下文判断。未能排除同名者或指代不明时，身份保持待确认。记录用于生成结果，不要求额外文件。

按记录分别判断以下关系，同一封邮件可以满足多项：

| 关系 | 纳入条件 |
|---|---|
| 本封正文提及本人 | 本封新写正文指向已确认的本人身份；任务取消、否定或转交的语句也可以构成提及 |
| 历史提及 | 引用内容指向已确认的本人身份；不能覆盖本封正文的独立判断 |
| 当前待办 | 当前有效要求的承担者为本人，动作及必要条件有正文依据；撤销或转交后的旧要求不纳入 |
| 待确认候选 | 有相关线索，身份或关系证据不足；放在候选中，不放进确认命中列表 |

发件、收件、抄送字段、签名和附件中的命中保留各自位置，不能代替本封正文的判断。用户要求这些范围时按相应关系处理。地址未出现在可见收件字段中，不证明邮件与本人无关；密送、转寄及群组投递需要相应证据，不能反向猜测成员或原始收件人。

从满足用户筛选关系的记录生成确认结果与待办，再列必要的待确认项。覆盖不足时说明缺少哪些身份映射或邮件范围；“已确认地址无命中”不能扩写为“没有提到你”。

## 附件导出

`ExportAttach: true` 让客户端生成临时附件。它不决定用户交付目录。导出辅助命令将结果保存到新的目标目录；目标文件、命名冲突和导出失败需要有可核对记录。

```text
python scripts/coremail.py export --params "<读取参数.json>" --out "<新的导出目录>"
python scripts/coremail.py export --params "<读取参数.json>" --out "<新的导出目录>" --apply
```

使用客户端给出的 `filename`/`name` 和 `tmpFile`/`path` 关联附件。附件可能以无扩展名的 `att_N` 文件存在；`MailStruct` 可提供附加线索。仅靠相同字节数无法区分多个同尺寸附件。来源映射有歧义时保留原始文件名或临时标识，并说明映射未确认；不得猜测文件归属。元数据指示有附件却未找到文件时，报告附件缺失；保存了元数据不等于附件导出完整。

导出工具根据 `mailAttachments` 的明确名称与路径关联保留原名。名称必须是安全的单个文件名，全部输出名称不得冲突；满足这些条件的附件保存为 `files/<原名>`。缺少映射、原名不安全或名称冲突时使用 SDK 文件名。两个等长附件以各自路径区分，不按大小分配名称。

`manifest.json` 的 `files` 记录 `source`、`stored`、`kind`、`original_name`、`size` 和 `sha256`；`name_source` 说明保存名称的来源，`name_fallback` 说明回退原因。原名和保存名分别保留，避免将回退文件名当成邮件中的附件名。

存在合法 `MailStruct` 时，工具将 `flags == 5` 的附件声明数量与去重后的实际附件数量比较。数量不符或结构损坏会在创建输出目录前失败。缺少 `MailStruct` 或其内容为空时，`manifest.attachment_inventory.status` 为 `unknown`；文件复制成功不证明邮件全部附件已覆盖。

`export` 默认请求 `bodyType: All` 和 `ExportAttach: true`，参数文件可指定所需正文格式。输出目录必须尚不存在。复制失败时保留已写文件和错误中的 `partial` 状态；不得将部分目录作为完整交付。

附件名是不可信路径。输出路径必须留在授权目录，禁止 `..`、绝对路径或其他名称成分逃出目标。不要覆盖现有用户文件。核对附件数量、字节数和可读取状态；声明哈希比对时须实际计算。

保存附件不等于解压、执行或提交内容。用户要求解压时保留原压缩包，检查条目路径和名称编码；乱码修复需要编码证据。文档、图片和其他内容分析交给对应能力；不把一种历史文件类型推广到全部附件。
