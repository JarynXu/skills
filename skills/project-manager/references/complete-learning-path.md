# Complete project-management learning path

Use this route when the agent lacks a broad project-management mental model. For a focused request, follow the direct routes in `SKILL.md`.

1. Read `core/project-truth-and-authority.md` to learn sources of truth, mandate, decision states, governance and role authority.
2. Read `core/adaptive-management-system.md` to tailor predictive, agile, flow-based and hybrid controls to project characteristics.
3. Read `practices/scope-requirements-and-change.md` for product/project scope, requirements, decomposition, acceptance and change authority.
4. Read `practices/schedule-estimation-and-dependencies.md` for dependency networks, estimation, critical path, milestones, rolling-wave plans, throughput forecasting and compression.
5. Read `practices/cost-resources-and-procurement.md` for budgets, actuals, EVM, reserves, staffing/capacity, vendors and commercial constraints.
6. Read `practices/risk-decisions-stakeholders-and-communications.md` for RAID, quantitative risk, decision latency, stakeholder engagement, status and escalation.
7. Read `practices/quality-acceptance-release-and-transition.md` for quality evidence, UAT, go/no-go, cutover, operational transition and acceptance.
8. Read `practices/agile-flow-and-hybrid-delivery.md` for Scrum/Kanban/flow/project interfaces, empirical forecasting, release planning and coherent hybrid patterns.
9. Read `practices/project-recovery-closure-and-benefits.md` for troubled-project recovery, reforecasting, options, closure, lessons and post-project benefits.
10. Read `technologies/control-plane.md` before creating or updating project controls from workspace evidence. Use `scripts/inspect_project_system.py` and `scripts/plan_project_controls.py` to expose source/authority gaps without writing project artifacts.
11. Read `technologies/tool-routing.md` for work trackers, scheduling, spreadsheets, documentation, communications, finance/procurement, QA/release systems and automation boundaries.
12. Use `scripts/project_metrics.py` when EVM, PERT or throughput Monte Carlo is decision-useful; preserve model assumptions and never turn a calculation directly into an approved commitment.
13. Enter `library/curriculum.md` when the agent needs source-backed professional learning. It routes PM² governance/lifecycle, GAO schedule/cost/agile guidance, the Scrum Guide, Kanban flow guidance, and the U.S. Digital Services Playbook into one coherent learning sequence.
14. For narrow lookup, use `scripts/offline_library.py search ...` against processed Markdown. Use `originals/` only to verify exact official bytes, pages, version, license or provenance.
15. Read `library/restricted-canon.md` before relying on PMI/PMBOK, PRINCE2, ISO or commercial publications. Learn from authorized current editions when a project formally adopts them; do not reconstruct proprietary standards from memory or copied fragments.

After learning, return to the actual project. Its sponsor/governance, contracts, product authority, finance/procurement systems, project tools, specialist evidence and observed delivery state override generic recollection. Project management is an integration discipline; broad knowledge does not transfer other roles' decision authority to the project manager.
