# CREATE：正向建立产品定义

从目标、问题、用户、场景和约束建立产品模型与功能规格时读取。

## 10. CREATE 模式

### 10.1 从问题而不是功能开始

不要直接把用户原话改写成功能清单。

建立链路：

```text
业务目标
→ 用户问题
→ 用户需求
→ 使用场景
→ 产品能力
→ 产品行为
→ 验收标准
→ 成功指标
```

链路缺失时，显式记录缺口。

### 10.2 建立用户需求

用户需求应描述情境、目标和价值，而不是界面或功能名。

推荐形式：

```text
当……时，
某类用户需要……，
以便……。
```

### 10.3 建立业务对象

每个重要对象至少定义：

- 名称；
- 业务含义；
- 唯一标识；
- 关键字段；
- 所属关系；
- 与其他对象的关系；
- 创建方式；
- 生命周期；
- 删除、归档和恢复规则；
- 可见范围；
- 数据来源。

### 10.4 建立流程

每条核心业务流程至少定义：

- 触发条件；
- 参与角色；
- 前置条件；
- 主流程；
- 决策点；
- 分支流程；
- 异常流程；
- 结束条件；
- 对象和状态变化；
- 通知；
- 审计要求；
- 外部依赖。

### 10.5 建立状态模型

任一对象存在两个或更多业务状态时，应建立状态模型。

至少定义：

- 状态名称和含义；
- 进入条件；
- 退出条件；
- 允许操作；
- 触发角色；
- 自动迁移；
- 可逆性；
- 超时和失败；
- 通知；
- 历史记录。

### 10.6 建立权限模型

存在两个或更多角色，或不同用户看到的数据和操作不同，则创建权限矩阵。

至少检查：

- 页面或能力权限；
- 对象级权限；
- 操作级权限；
- 字段级权限；
- 数据范围权限；
- 状态相关权限；
- 导出和批量操作权限；
- 自我操作限制；
- 权限变化中的处理；
- 无权限时的产品行为。

### 10.7 建立功能规格

一个可独立定义、演进或交付的产品能力应建立：

```text
07-features/<feature>/
```

不要为一个按钮、字段或纯 UI 元素单独建立功能目录。

功能规格至少应覆盖：

- 功能目标；
- 关联用户需求；
- 用户和角色；
- 场景；
- 前置条件；
- 输入和输出；
- 主流程；
- 分支和异常；
- 业务规则；
- 状态；
- 权限；
- 数据和内容；
- 通知；
- 依赖；
- 非范围；
- 验收标准；
- 未决问题。
