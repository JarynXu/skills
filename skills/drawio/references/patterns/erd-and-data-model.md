# ERD and data models

Represent entities, identifiers, important attributes, relationships, and cardinality. Choose one notation family and use it consistently. Use entity-relation routing/crow's-foot markers when appropriate.

Avoid turning every implementation column into a large diagram when the user asks for a conceptual model. For logical/physical models include PK/FK, nullability, types, indexes, or constraints only at the requested level. Group schemas/domains when they are real boundaries.
