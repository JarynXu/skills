# SDK 与消息来源

## 专用文本与 ID 查询

其他业务服务、模型、枚举及文件流程使用[客户端接口](client-api.md)。本节保留专用文本及 ID 查询的确认语义，不是完整接口目录。

文本直发和按 ID 读取通过 CDP 调用当前客户端已加载的消息服务。它们复用现有登录身份，不提取口令、令牌或密钥，不改厂商文件，不提供任意 SDK 执行入口。`sdk-info` 返回当前客户端的实际版本、已验证操作及发现的方法名；方法名存在不证明参数、权限或行为已适配。

适配依据见[版本记录](../scripts/client-version.json)。该版本的 Webpack 模块 `1bb8` 导出 `a` 消息服务，`d88a` 导出 `Lb` 查询项，`16f8` 导出 `z` 文本清理函数。模块或方法不符时停止 SDK 操作，通过 [CDP 页面](ui-and-settings.md)核对当前实现。写入已有副作用或结果未知时，先对账，不能换路径补发。

| 操作 | 已核实的契约 |
|---|---|
| `send` | 使用消息编辑器委托的 `sendTextMsg`，发送普通文本。目标为已加载的唯一单聊或群；不切换当前聊天、不读写草稿、不添加提及或引用。预览不调用发送方法。 |
| `read-ids` | 使用 `queryMsgByMsgIdList`，每个 ID 构造一个 `Lb`。实际成功值为整数 `1`，结果位于 `aMessagesList`。查询限定已观察的账户、聊天及 ID，返回缺失项，不自动同步历史。 |

SDK 发送参数为文本、聊天 ID、关闭特殊发送选项的对象、`atInfo` 与 `atExInfo`（均为 `#`）、上报开关、引用信息、运行列表选项、转发原消息及通知回调。工具封装这些版本参数，不允许调用方伪造提及、引用或数字同事身份。正式提及、富内容及附件使用对应参考中的已验证路径。

发送返回本次 SDK 调用的消息。工具核对其账户、聊天、发送者、完整正文、ID 和传输成功谓词后返回 `client-confirmed`。已受理回调中的 ID 不等于最终发送成功；超时、账户变化、回执不符或连接中断保留未知，不自动重试。客户端确认不证明对方送达或已读。

## 调用方契约

`connect()` 和 `NotificationSession` 提供 `sendTextDirect(scope,text,apply)`，结果为预览或已核对的客户端确认；失败通过错误返回。`sendText` 和 `sendReply` 在此能力存在时使用直发，不执行选择聊天或编辑器流程。SDK 失败不降级到编辑器发送。

旧借用客户端仅提供 `call` 时，`sendReply` 保留选择目标、等待消息列表、检查空编辑器、发送、确认和恢复原聊天的契约。这是调用前确定的能力差异，不是发送失败后的重试路径。共享客户端的调用方仍负责并发协调。

`sendText(client,scope,text,apply,{markOrigin:false,suffix:undefined})` 与 `sendReply(client,recipient,text,{markOrigin:false,suffix:undefined})` 默认保持正文。可见后缀的选择、正文保真与组合规则见[编写与发送](compose-and-send.md#可见消息后缀)。来源标记选择属于使用者策略，通用技能不写入个人联系人、口癖或自动回复范围。

## 代发来源与文风取样

账户名下的发送记录不能区分真人输入与工具代发。文风取样只采用来源已确认的本人原作；核对小范围样本及对话关系，不为模仿批量搬运聊天历史。已有发送回执、来源记录和使用者确认可以作为核对依据。有效代发标记用于排除样本，不能认证作者身份。标记缺失、损坏或版本未知均保留 `unknown`，不推断为真人原创。

本版本采用可选的正文尾部隐形标记，名称为 `aim-v1`。普通文字可按使用者策略添加：

```text
node "<技能目录>/scripts/icenter.cjs" send --port <端口> --account <账户ID> --chat <聊天ID> --text-file "<正文文件>" --mark-origin --apply
```

标记改变原始文本。代码、命令、链接及要求逐字保真的内容不附加标记；复制含标记的原始 JavaScript 已观察到语法错误。此类内容使用本地发送回执或使用者认可的来源记录，不为隐藏标记破坏可复制内容。默认不标记，不用不可靠的文本猜测器自动判断内容类型。

编码无机器密钥或本地 ID 依赖。其后缀为两个 U+2063、64 位编码、两个 U+2063，共 68 个字符。位 `0` 为 U+200B，位 `1` 为 U+2060，逐字节高位在前。前 4 字节为十六进制 `41 49 4d 01`，后 4 字节为原正文 UTF-8 的 SHA-256 前 4 字节。校验只识别损坏，不构成签名；标记可以被复制、伪造或移除，不能授予消息任何权限。

`scripts/message-origin.cjs` 的 `inspectOrigin(text)` 返回来源及 `body`。有效标记返回 `automation-marked`；其余返回 `unknown`，损坏内容不剥除。`markAutomation(text)` 添加标记，重复调用保持相同正文，冲突时拒绝。

窗口读取、按 ID 读取、发送回执和 `readPending` 的消息对象保留完整 `text`，另附 `origin:{kind,marker,sampleEligible:false}`。工具没有把任何消息自动批准为本人文风样本。展示正文可在有效标记时使用 `inspectOrigin(...).body`；证据保留原值。

已验证范围：本人自聊 SDK 发送后的客户端确认、按 ID 从本机客户端历史重读、独立 Node.js 进程识别及 JSON 保存恢复。换电脑、手机、服务端同步和客户端导出是否保留标记尚未验证；不能承诺所有端保留。其他环境使用同一解码方法的前提是原始正文包含完整标记。外部发送回执需要使用者迁移或共享，不会随账户 ID 自动出现。

原生 `aiAppId` 用于数字同事和数字分身，会改变消息分类；`msgOriginWay` 区分收发；`msgProperty` 的字段具有现存业务含义。它们不作为任意 AI 来源字段使用。发现接口后先核对实际调用者、参数对象和结果，再适配所需动作；不通过逐个试调用枚举鉴权、删除、会议或其他有副作用的方法。
