# 编写与发送

发送使用[客户端接口](client-api.md)，保留当前聊天和草稿。沿用已给的发送授权，核对登录账户、收件人 ID、正文、附件与关联消息。读取授权不能替代发送授权。

## 普通文本

send 从 UTF-8 文件读取正文，CRLF 转 LF，其余字符保留。它调用实际消息服务，核对本次调用返回的消息 ID、账户、聊天、发送者、完整正文和传输成功状态。目标为已加载的唯一单聊或群，不要求当前选中，不读取或覆盖编辑器。

    node "<技能目录>/scripts/icenter.cjs" send --port <端口> --account <账户ID> --chat <聊天ID> --text-file "<正文文件>"
    node "<技能目录>/scripts/icenter.cjs" send --port <端口> --account <账户ID> --chat <聊天ID> --text-file "<正文文件>" --apply

预览不发送；--apply 不替代授权。客户端会改写的文本在发送前拒绝，不静默替换字符。可选 --mark-origin 的适用范围及来源判断见[SDK 与消息来源](sdk-and-origin.md)；代码、命令、链接及逐字内容保留原文。

## 草稿、回复和提及

草稿使用 messages.saveDraftAtChatRoom、clearDraftAtChatRoom。先读取现有草稿、附件、引用和提及，明确已有内容的处置；不能用保存新正文覆盖用户原作。保存的依据是客户端草稿记录及重读，不等同于消息已发送，也不保证编辑器当前展示已刷新。

回复、引用、线程、卡片及富文本使用 messages 中对应方法和模型。先用 sdk-describe 核对原消息参数、回复信息和正文结构；需要原生消息方法时使用原消息引用标记。不能复制文字冒充转发或关联回复。

正式提及需要客户端支持的结构化身份及消息属性。核对群、成员 URI 和 unionID，依据当前构造与发送方法生成 atInfo、atExInfo 等字段；发送后重读原生字段核对。正文中的 @姓名 或 HTML 片段不证明正式提及。@所有人 需要覆盖全群提醒的授权，不能用来代替找不到单人的情况。普通 send 不附加提及或引用。

## 附件与发送结果

新文件使用 send-file 的准备与发送流程；图片、语音、视频、卡片和其他内容见[文件与收藏](files-and-collections.md)。图片作为文件发送时保持文件类型，不能写成图片消息。文件来源、名称、内容和已确认 ID 分别核对。

客户端确认发送不证明对方送达或已读。按钮完成、输入框清空、消息气泡出现和已受理回调各自不足以证明发送完成。通用 SDK 返回 returned 只证明方法返回，业务成功按原生状态和目标新状态判断。

断连、超时、账户变化或回执不符保留结果未知、阶段及已有受理 ID。通过原账户、聊天和消息 ID 对账，不重发、不改走页面补发。明确失败与未知分别报告；保留草稿、源文件和已有证据。
