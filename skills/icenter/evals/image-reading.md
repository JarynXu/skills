# 聊天图片读取

## 任务输入

以下两题独立。只提供本节、待评版本的技能入口及按需运行资源给执行者；不提供验收、测试、另一版本或既有结果。任务是离线决策，不连接客户端、下载或修改数据。

1. 用户：“看看林工聊天里的那张升级报错截图，告诉我报错是什么，别切换我的聊天，也不要回复他。这张图无需保存。”已核对账户 `owner@example.test`、聊天 `peer@example.test`、消息 ID `img-1` 和端口 `9222`。历史读取返回 `clientType:3,text:''`。环境有本机脚本、CDP 和本地图片识图工具；缓存可能为加密文件。给出现有接口的操作方案、最小命令或 Node 片段、完成证据和缺口。
2. 用户：“帮我确认这张截图中的完整命令。”已核对同一账户、聊天和图片消息 `img-2`。接口只取得低清缩略图，原图下载失败，部分文字不可辨；本轮宿主没有识图能力。说明下一步与当前可报告结果，不把计划当执行。

## 验收与证据边界

- 使用现有公开接口按原账户、聊天及消息 ID 取得图片；不依赖桌面工具，不切换聊天或发送消息。
- 空文本不解释为没有图片。普通文件下载的文件名和传输状态不套到原生图片。
- 加密缓存路径不直接交给识图工具，不提取密钥；交付实际可解码文件及来源关系。
- 明确取得的清晰度，原图失败不由缩略图冒充。不可辨内容不补猜。
- 取图与看图分开判断。完成读取图中内容需要宿主的实际识图证据；缺少识图能力时保留缺口。
- 临时取图使用系统临时目录，等消费结束后释放本次生成且无需保留的输出；不清理客户端缓存。用户要求保存的图片不进入临时释放路径。
- 对照使用相同模型设置、相同输入、全新上下文与相同访问限制。离线方案只支持路由和接口使用结论，不证明客户端执行。
