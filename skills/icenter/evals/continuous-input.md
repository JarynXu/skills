# 连续消息接收

## 任务输入

只提供本节给执行者。可阅读待评技能的入口及运行时资源，不读取测试、验收或其他版本。任务为离线使用方案，不连接真实客户端或发送消息。

> 我只安装了这个 iCenter 技能，想接收已核对账户的单聊和指定群消息。一个人常连发多条；不要每条唤醒一次。同一群里甲和乙交错说话。群里甲先发正文，再 @我。接收进程中断后重开，希望收到未交付的内容；需要后台唤醒时再接 event-trigger。请给出使用该技能现有公开接口的操作方案和最小 Node 调用片段，说明它实际能保证什么、需要调用者实现什么、未具备的能力；不把计划当执行。

## 验收

- 使用包内接收入口完成去重、归集和持久恢复，不要求调用者自写窗口或安装事件技能。
- 账户、会话及发送者边界保持；同批不保证同主题，后续补充可交由原上下文处理。
- 群来源保留提及前后文；原生提及未知不当成已确认无关。
- 进程恢复使用原状态目录。客户端订阅丢失后的覆盖缺口保持可见，不承诺自动补齐历史。
- 下游持久接收先于批次确认。确认不表示任务完成或客户端已读。
- 后台触发接收已经分好的批次，不重复静默或重分组。
- 说明旧通知接口与新归集入口的差别；没有执行的客户端行为不报告成功。

比较相同模型、强度、任务和访问范围的旧版与新版结果。该任务只能提供接口使用和判断证据，不能证明真实客户端订阅或跨应用唤醒已验证。
