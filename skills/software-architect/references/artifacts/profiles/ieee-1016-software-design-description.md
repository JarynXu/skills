# IEEE 1016 Software Design Description Profile

Use this profile only when the governing request explicitly identifies an IEEE 1016-2009 **Software Design Description (SDD)**. Do not apply it to a generic "System Design Document" or infer it from `SDD` alone.

## Profile identity and status

- **Standard:** IEEE 1016-2009, *IEEE Standard for Information Technology—Systems Design—Software Design Descriptions*
- **Authority:** the official [IEEE Standards Association record](https://standards.ieee.org/ieee/1016/4502/)
- **Status:** Inactive-Reserved; IEEE records an inactivation date of 2020-03-05 and no active replacement project
- **Scope:** recording and communicating software design information, including high-level and detailed design and reverse-engineered descriptions

The public IEEE record confirms applicability and status, but not the full normative content. Do not claim IEEE 1016 conformance from this profile alone.

## Establish the governing edition

1. Confirm that the request means Software Design Description rather than another expansion of SDD.
2. Determine whether IEEE 1016-2009 is contractually required despite its inactive status or whether a local adaptation supersedes it.
3. Obtain an authorized copy of the governing standard and any contractual tailoring when exact conformance matters.
4. Record the edition, amendments, local adaptations, and precedence before composing.

If the authorized normative source is unavailable, generate only a provisional artifact under the general document-generation method and disclose that IEEE 1016 conformance was not verified.

## Build the conformance profile from the authorized source

- Extract every applicable normative content and organization requirement into a clause-linked checklist.
- Distinguish required information from examples, notes, rationale, and permitted alternatives.
- Capture requirements for design-language selection without assuming a particular notation or design method.
- Map each required design statement to authoritative project knowledge and its verification state.
- Record which requirements apply to high-level design, detailed design, reverse engineering, or all applicable scopes.
- Preserve required relationships among design information instead of treating the standard as a flat chapter list.
- Identify permitted media and organization-specific tailoring without changing design meaning.

The official public record establishes that the standard is methodology-neutral, design-language-neutral, and usable in paper, database, development-tool, or other media. Treat any more detailed structure as `[UNKNOWN]` until verified from the authorized standard or a governing local profile.

## Validate the result

Before claiming conformance:

- satisfy every applicable item in the clause-linked checklist;
- trace each design statement to the stated source revision;
- document exclusions, tailoring, unresolved conflicts, and unavailable evidence;
- verify both information content and organization against the governing edition;
- label the artifact's exact standard edition, status, conformance claim, and local adaptations.
