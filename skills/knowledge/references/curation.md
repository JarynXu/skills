# 取舍与提炼

用于工作中的知识变化、收尾和材料整理。先判断什么属于共享知识，再提炼可用结论；不要先生成聊天摘要或工作总结，再把它归档。

## 写入前判断收录资格

以可独立核对的主张为单位，查看当前要求、最终产物、相关来源与既有主题。区分最终采用的行为与中途尝试；同一次谈话中的不同主张可以有不同处置。

逐条判断以下关系，不要求生成台账或评分：

- **读者与用途**：团队中的谁在什么后续理解、决策或执行任务中需要它？不知道会导致哪种误用、误判或重复调查？“这次发生过”或“对说话者很重要”本身不是共享价值。
- **适用范围**：它描述项目、组件、某个受支持版本或共享环境，还是只描述一个人的偏好、本机状态、私人路径或助手交互方式？范围具体不等于私人，关键是共同工作是否依赖它。
- **权威与性质**：这是可验证事实、已接受的项目决定、建议、推测还是个人要求？事实靠相关证据，团队要求靠有权决定者的明确采纳；不能以“用户说过”“有人做过”或删掉人称替代这些依据。决定已接受也不等于已经实施。
- **证据与边界**：来源实际支持哪些条件、结果与原因？个人是信息来源不构成拒收理由，但一个人的单机成功不能证明团队通用要求。无法访问、互相冲突和未经核验必须保留区别。
- **现有知识与增量**：读取主要维护位置，看是否已经准确覆盖。新增知识应改变后续读者的理解或行动，不能只是换一种说法重复已知事实。

个人偏好、个人工具选择、临时代理和工作目录通常不进共享正文；只有团队确实依赖且有证据支持的环境要求，才按相应范围维护。个人内容也不自动转存到新文件：没有明确授权的个人记录目的地，就排除，不擅自创建私人记忆库。共享来源中涉及个人的必要职责或决定权可以保留；与核对结论无关的姓名、联系方式和私聊原文不复制。

未通过的候选不进入正文改写。若缺少关键证据会影响本次结论，继续核查或说明具体缺口；若只是个人材料且没有共享增量，保持知识不变。敏感数据先排除或按授权处理，共享价值不扩大复制或披露权限。

## 从合格候选提炼主题结论

提炼“对象在什么条件下有什么行为、约束或选择，为什么影响后续使用”，保留证据支持的原因、例外与状态，不保留说话顺序。一个人报告的发现可以被核验为项目事实；个人要求不能靠改写成“项目应当”获得权威。

“调了三次才成功”是经历；“这个参数只在进程启动时读取，改文件后已有进程不会自动生效”是机制。后者要由加载实现或恰当试验支持，不能只从重启成功反推。没有原因证据就不补写设计理由；尚未确认的推测不能润色成确定结论。

以规则或使用问题为单位，而不是一个文件、一次任务或一场会话一个知识点。一次重构可能没有对外知识变化；没有源码改动的调查也可能推翻错误操作说明。未采用的方案不写成当前设计，有依据且仍解释选择的取舍原因可以进入已有决定主题。

当前任务取得且前提未变的证据可以复用，先查有关主题及必要依赖，不为每次收尾重新扫描全部工程。引用最接近结论且读者可核对的源码、配置、测试或决定记录；原始谈话确是唯一依据时，只保留必要的来源定位、权威范围和不确定性，不搬运私人原话，也不伪造正式决策文档或审核记录。

## 对照现有知识决定处置

| 已查明的情况 | 处理 |
| --- | --- |
| 当前说明错误、不完整，或这次改变了其中的事实 | 更新原主题及真正受影响的派生说明；优先消除误导，不用新文章回避修旧文 |
| 有共享增量，现有主题能承担且与它一起变化 | 补入原文，保持条件、例外和来源相邻 |
| 有独立用途和维护责任，现有主题不能合理容纳 | 在授权范围内新增完整主题并接入分类；不是按会话、日期或工作量追加文章 |
| 原处资料准确、维护明确，只缺项目使用入口 | 链接原处并补必要使用语义，不复制另一套权威正文 |
| 旧做法已替换或不再适用 | 更新当前指引，按有效历史与授权处理替代关系；仍受支持的旧版本单独限定 |
| 已准确覆盖，或仅有个人材料、任务过程、没有后续用途的局部细节 | 保持不变，不创建“经验”“无变化”或私人备忘录来凑产出 |
| 缺关键来源、冲突未查清或无目标写入权限 | 说明缺口与下一步，不冒充已入库，也不冒充没有共享增量 |

这些是处置结果，不要求每次输出全部栏目。一个会话可以同时更新契约、引用决定、保留诊断依据并丢弃过程噪音。

## 按用途保留必要条件

业务含义、契约、跨对象关系、机制、约束、操作条件和有依据的决定原因面向后续任务维护。项目正式政策归指定位置；AGENTS 负责工作入口和强制约定，不是所有经验的收纳处。知识维护不能代替政策批准或自动修改通用技能。

任务进度、等待结果和临时文件定位留在已有任务状态；原始报错、工单经过、测试输出留在对应记录。只有因果、复现、恢复或解释决定需要时，主题中才保留最小事件序列、触发条件、关键分支及结果，并链接原证据。事故时间线和决策沿革可以是知识，不等于逐条聊天记录；不要因为反流水账而删除其诊断或审计价值。原始证据按既有留存要求保全，不因不收录正文而删除。

一次测试通过通常只证明该次结果；若确认未知的兼容边界，收录所验证的条件而非“已全面验证”。已证实的高影响机制不必等事故重复发生。个人绕过无团队依据时排除；仍影响团队受支持环境的临时措施应写触发条件、版本、作用与代价、退出条件，并指向问题或变更来源，不能永久推广。

通用教材保持原处，本项目采用的版本、适配限制或易误用语义可以说明。已有配置、清单或生成参考能直接回答时，链接它并补必要语义，不抄写另一份无人维护的全量值。

## 写成后来的人能使用的正文

围绕通过准入的主题说明对象、条件、行为与影响。决定说明目标、选择、代价和当前状态；操作说明给出前提、执行与结果判断。具体配置值、协议字段和命令在正确使用确实需要时保留，不把个人绝对路径换成占位符就自动视为可收录规则。

没有参加谈话的人应能直接理解结论，不必重演这次协作。必要默认值不能为了去重藏在多次跳转之后；来源不能只是模糊的“已沟通确认”，也不需要附整段对话证明自己做过工作。

最终核对结论是否仍保持原有范围、权威与不确定性。按用户要求报告实际变更及关键排除理由；真正无增量时不写文件。无法核查要另说，不能与无变化合并。
