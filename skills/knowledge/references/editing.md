# 按需使用工具

优先复用项目的校验命令与 Git diff/status。以下工具仅服务于采用 OKF 的文件知识库，全部只读；不需要它们完成的任务，不为调用工具而调用。知识目录可以叫任意名字，也不需要 Git 或 AGENTS 副本。

## 局部检查

```sh
python <skill>/scripts/kb.py check --bundle <知识目录> --workspace <允许读取来源的目录> --file <相对知识目录的文档.md>
```

`--file` 可重复；省略时检查全库。没有 `--workspace` 时读取边界就是 bundle，确有兄弟工程来源时显式扩大到适当的项目目录。路径越界、不可读取、符号链接或 Windows 目录联接会报告，不自动放宽权限。

默认解析选中文档、确认其本地链接和来源路径存在，不读取所有来源内容。添加 `--sources` 才核对所选文档已有的 sha256；相同文件本次只哈希一次。添加 `--require-index` 才检查目录索引，并在局部模式读取有关的祖先索引。此选项是可选的导航规则，不是 OKF 强制要求。

移动或删除文件需要检查入链，仅查新文档不能证明旧链接全部修好。可以先搜索入链并逐个检查，或在范围较大时执行一次全库检查。纯措辞修订不要求前后各扫描全库。

## 来源变化的候选影响

```sh
python <skill>/scripts/kb.py impact --bundle <知识目录> --workspace <来源边界> --source <相对workspace的源文件>
```

这里扫描知识文档的来源与链接，不哈希所有源码。结果分 direct（直接来源）、derived（沿 sources 继续派生的知识）和 link_references（普通导航入链）。前两者用于复核事实，后者用于引用和迁移检查，不把导航关系冒充事实依赖。支持多级、目录来源、重复和循环；删除后的缺失路径仍可返回候选，同时保留错误退出状态。候选不是必须修改清单，新依赖、未记录调用和现场变化仍需单独调查。

## 生成一个来源条目

```sh
python <skill>/scripts/kb.py source --bundle <知识目录> --workspace <来源边界> --document <文档.md> --file <源文件> --id <稳定标识>
```

只打印正确的相对路径；项目确实使用文件指纹时添加 `--hash`。没有哈希不表示没证据，有哈希不表示已经审核。不能用刷新条目掩盖未核实的内容。

## 结果与范围

退出码 0：本次所选范围没有阻塞问题；1：发现问题；2：依赖、输入或环境导致检查未完成。查看 coverage：局部通过不代表全库通过，没启用来源检查不能称来源未变化。

format 表示本检查器支持的 OKF 核心语法，consistency 表示可机械检查的引用一致性，navigation 表示显式要求的导航规则，source 表示来源路径或指纹问题，review 表示内容复核提示。脚本不做通用 OKF 认证、语义审核、运行测试、全量秘密扫描或各渲染器的锚点一致性验证。

没有格式问题时，内容取舍、证据是否支持结论、职责边界和表达仍由实际评审决定。不要因某个退出码扩展无关清理，或把旧告警当成本次引入的问题。
